# Wi-Fi 无 IP 问题修复记录（2026-10-22）

## 现象

设备能扫描到大量 AP，`wlp1s0` 也显示 UP，但**始终没有 IP 地址、没有默认路由、上不了网**。

```
wlp1s0  DOWN  <NO-CARRIER,BROADCAST,MULTICAST,UP>
（无 IPv4）
ip route  →  只有 172.16.42.0/24 dev usb0
```

## 根因：三个组件互相打架

排查发现同一块网卡被**三套机制同时管理**，彼此冲突：

| 组件 | 配置 | 问题 |
| --- | --- | --- |
| `systemd-networkd` | `/etc/systemd/network/25-wlp1s0.network` → `DHCP=yes` | 只管 DHCP，**不负责关联 AP** |
| `wpa_supplicant` | `/etc/wpa_supplicant/wpa_supplicant.conf`（K50G） | 配置指向的 AP 当时不在范围内 |
| `NetworkManager` | 未忽略 wlp1s0 | 但**没有任何已保存连接** |

关键点：`networkd` 只声明了 `DHCP=yes`，它**不会主动关联 Wi-Fi**；而 `NetworkManager` 状态是 `disconnected`、`GENERAL.REASON: 42 (The supplicant is now available)` —— 说明 NM 已就绪但没有连接配置可用。

三条路都没走通，于是网卡一直是 `no-carrier`。

## 修复方案：让 NetworkManager 独占 wlp1s0

选择 NM 而非 networkd，理由：

- NM 原生支持 Wi-Fi 关联 + 认证 + DHCP 全流程
- 连接配置持久化，支持隐藏 SSID、autoconnect、优先级
- `networkctl` 只管有线/DHCP 场景，不擅长 Wi-Fi

### 步骤

**1. 移除 networkd 对 wlp1s0 的管理**

```sh
mkdir -p /root/wifi-backup
cp /etc/systemd/network/25-wlp1s0.network /root/wifi-backup/
cp /etc/wpa_supplicant/wpa_supplicant.conf /root/wifi-backup/
rm -f /etc/systemd/network/25-wlp1s0.network
systemctl restart systemd-networkd
```

**2. 明确 NM 管理范围（保持 usb0 unmanaged）**

`/etc/NetworkManager/conf.d/10-manage-wifi.conf`：

```ini
[keyfile]
unmanaged-devices=interface-name:usb0
[device]
wifi.scan-rand-mac-address=no
```

> `usb0` 是调试通道（172.16.42.1），必须保持 unmanaged —— 实测它本来就由 USB gadget 自行配置 IP，不依赖任何网络管理器，所以改动 wlp1s0 不会影响它。

**3. 建立连接配置（隐藏 SSID）**

注意：目标热点 `K50G` 是**隐藏网络**，扫描结果里显示为空 SSID：

```
SSID: (空)   BSSID: 9A:AA:0E:D7:D5:72   SIGNAL: 100   SECURITY: WPA2
```

因此必须设 `hidden=true`，否则 NM 不会主动探测它。

`/etc/NetworkManager/system-connections/K50G.nmconnection`：

```ini
[connection]
id=K50G
uuid=<随机>
type=wifi
interface-name=wlp1s0
autoconnect=true
autoconnect-priority=10

[wifi]
mode=infrastructure
ssid=K50G
hidden=true

[wifi-security]
key-mgmt=wpa-psk
psk=<密码>

[ipv4]
method=auto

[ipv6]
method=auto
```

```sh
chmod 600 /etc/NetworkManager/system-connections/K50G.nmconnection
nmcli connection reload
```

> **踩过的坑**：先用 `nmcli connection add` 建连接时它工作正常，但**没有落盘** —— `/etc/NetworkManager/system-connections/` 仍为空。直接用 `nmcli connection up` 激活只在内存里生效，重启即丢。因此改为手写 `.nmconnection` 文件。

## 验证结果

### 即时生效

```
wlp1s0:connected:K50G
IP:       192.168.72.140/24
默认路由: default via 192.168.72.54 dev wlp1s0  ← 此前完全没有
网关 ping: 3/3 received, 6ms
外网 ping: 3/3 received (223.5.5.5), 61ms
HTTP 检查: HTTP/1.1 204 No Content, x-networkmanager-status: online
```

### 重启后自动连接

重启后（`uptime 0 min`）立即检查：

```
wlp1s0:connected:K50G
IP: 192.168.72.104/24          ← DHCP 重新分配
默认路由: via 192.168.72.54 dev wlp1s0
外网 ping: 3/3 received, 61ms
nmcli networking connectivity: full
```

**完全自动，无需任何手动操作。**

### 调试通道未受影响

```
usb0   UP   172.16.42.1/24
```

`25-wlp1s0.network` 移除后，`networkctl list` 中 wlp1s0 变成 `unmanaged`，usb0 始终是 `unmanaged`（本就如此）。

## 现状总结

| 项 | 值 |
| --- | --- |
| 管理方式 | **NetworkManager 独占 wlp1s0** |
| 配置文件 | `/etc/NetworkManager/system-connections/K50G.nmconnection`（mode 600） |
| 隐藏 SSID | `hidden=true`（该热点广播空 SSID） |
| 自动连接 | `autoconnect=true`, priority 10 |
| 备份 | `/root/wifi-backup/`（旧 networkd + wpa_supplicant 配置） |
| systemd-networkd | 仍在运行，但不再管理 wlp1s0 |

## 换网络时的操作

```sh
# 扫描（含隐藏）
nmcli device wifi rescan; nmcli device wifi list

# 连普通网络
nmcli device wifi connect "SSID" password "密码"

# 连隐藏网络
nmcli connection add type wifi con-name "名字" ifname wlp1s0 ssid "SSID" \
  wifi-sec.key-mgmt wpa-psk wifi-sec.psk "密码" \
  802-11-wireless.hidden yes connection.autoconnect yes
nmcli connection up "名字"

# 企业认证 (802.1X, 如 eduroam/HKUSTGZ)
nmcli connection add type wifi con-name "HKUSTGZ" ifname wlp1s0 ssid "HKUSTGZ" \
  wifi-sec.key-mgmt wpa-eap 802-1x.eap peap 802-1x.phase2-auth mschapv2 \
  802-1x.identity "用户名" 802-1x.password "密码" connection.autoconnect yes
```

## 排查要点（备查）

1. **先分清谁在管网卡**：`networkctl list`（看 networkd）、`nmcli device`（看 NM）。两边都 `configuring/active` 就是冲突。
2. **NM 显示 `disconnected` + `reason 42`** 说明 supplicant 正常、只缺连接配置，不是驱动问题。
3. **隐藏 SSID 会在扫描结果里显示为空 SSID**，靠 BSSID 识别；必须 `hidden=true` 才能连。
4. **`ip link set up` 后仍显示 `DOWN`/`DORMANT`** 是未关联 AP 时的正常表现，不是故障。
5. **`nmcli connection add` 可能不落盘**：务必检查 `/etc/NetworkManager/system-connections/`，或用 `nmcli connection show <name>` 后确认文件存在。
